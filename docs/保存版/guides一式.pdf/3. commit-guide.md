# コミット操作ガイド（commit-guide）

commit と push の違いが分からないと  
「保存したのに反映されない」状態になります。

GitHub Desktop で行う  
“変更を記録する（コミット）” 操作をまとめたガイド。

## コミットとは？

- 変更を記録する操作  
- GitHub に送る前の “下書き保存”  
- コミットしないと Push できない  
- 後継者が変更内容を追跡できる  

---

## コミットの流れ（基本操作）

### 1. 変更されたファイルを確認する  
左側の **Changes** に変更されたファイルが一覧で表示される。  
- 追加されたファイル  
- 修正されたファイル  
- 削除されたファイル  

---

### 2. Summary（必須）を入力する  
変更内容を一言で書く欄。  
後継者が見ても意味が分かる内容にする。

例：  
- README を更新  
- ガイドの誤字修正  
- 画像を追加  

---

### 3. Description（任意）  
必要なら詳細を書く。

例：  
- 画像の差し替え理由  
- 修正箇所の補足  

---

### 4. **Commit to main** を押す  
これで変更が “main に記録される”。

---

## コミット後にやること（Push）

コミットしただけでは GitHub に反映されない。

1. 左上に **Push origin** が表示される  
2. **Push origin** をクリック  
3. GitHub に変更が送信される  

---

## 注意点（あなた専用メモ）

- Summary は必ず書く（空欄だとコミットできない）  
- 1コミット＝1目的にすると後継者が理解しやすい  
- コミット → Push の順番を忘れない  
- オフライン時はコミットだけしておいて、後で Push すればOK
